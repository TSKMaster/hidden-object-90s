# Hidden Object 90s — предварительная архитектура

## Статус и основания

Согласованные игровые требования описаны в [GAME_DESIGN.md](GAME_DESIGN.md). Этот документ фиксирует архитектурные принципы и предварительный подход к будущей реализации. Он не является поручением устанавливать зависимости или писать игровой код на текущем этапе.

## Предварительный стек

Рассматривается TypeScript + Vite + Phaser 3. Этот выбор предварительный, а не окончательно утверждённый. Зависимости пока не устанавливаются; проект сборки не создаётся.

## Архитектурные принципы

- Простая реализация и минимум зависимостей.
- Данные уровней отделены от игрового кода.
- Предметы хранятся в переиспользуемой библиотеке ресурсов.
- Новые уровни в рамках согласованных механик добавляются через данные и ресурсы без изменения игрового движка.
- Сложный редактор уровней на этапе MVP не создаётся.

## Предлагаемое разделение ответственности

Это логические части будущей реализации, а не требование создавать отдельный класс, сервис или пакет для каждой из них.

| Часть | Ответственность |
| --- | --- |
| Данные уровня | Ссылка на фон, перечень размещённых предметов и их преобразования |
| Библиотека предметов | Общие определения предметов: идентификатор, название для списка и ссылка на изображение с прозрачным фоном |
| Игровая сцена | Отображение фона и предметов по данным уровня, обработка нажатий |
| Состояние прохождения | Учёт найденных предметов, проверка завершения, сброс при перезапуске |
| Интерфейс | Список искомых предметов, отметки о находках, отображение завершения и управление перезапуском |

## Предварительная модель данных

Ресурс предмета и его размещение на уровне следует различать: изображение и название берутся из библиотеки, а положение определяется уровнем. Это позволяет использовать один ресурс на разных уровнях.

Предлагаемый состав данных:

| Сущность | Данные |
| --- | --- |
| Определение предмета | Уникальный идентификатор ресурса, отображаемое название, ссылка на изображение |
| Уровень | Идентификатор уровня, ссылка на фоновое изображение, базовые размеры сцены, список размещений |
| Размещение предмета | Уникальный в пределах уровня идентификатор размещения, ссылка на определение предмета, координаты X и Y, масштаб, угол поворота |
| Состояние прохождения | Идентификаторы найденных размещений и состояние завершения текущего уровня |

Для MVP все десять размещённых искомых предметов входят в список поиска. Список и сцена используют одни и те же данные уровня, чтобы их содержимое не расходилось. Состояние прохождения отделено от исходных данных уровня и сбрасывается при перезапуске.

Формат файлов, имена полей, единицы угла, точка привязки изображений и система координат пока не утверждены. Предлагается использовать единую систему координат относительно базовых размеров сцены; её точные соглашения нужно зафиксировать при переходе к реализации.

## Поток работы уровня

1. Прочитать данные уровня и получить необходимые ресурсы фона и предметов.
2. Отобразить сцену и сформировать список поиска из размещений уровня.
3. При нажатии на ещё не найденный предмет отметить его размещение как найденное и обновить список.
4. Сравнить количество найденных размещений с общим количеством искомых предметов; при совпадении завершить уровень.
5. При перезапуске очистить состояние прохождения и восстановить исходный список поиска.

Повторные нажатия на найденный предмет не меняют счёт найденных предметов. Для добавления следующего уровня потребуется подготовить его фон, при необходимости расширить библиотеку предметов и описать размещения в данных.

## Мобильный экран

Основная ориентация игры — горизонтальная (Landscape). Это утверждённое требование, независимо от предварительного статуса технического стека.

- При изменении размера экрана пропорции игровой сцены сохраняются.
- Фон и предметы масштабируются совместно, с согласованным преобразованием их положения.
- Координаты предметов должны оставаться корректными при изменении размера экрана; адаптация отображения не должна нарушать размещение, заданное данными уровня.
- Области нажатия должны соответствовать тем же преобразованиям, что и отображаемые предметы, и совпадать с их видимым расположением.
- Список предметов и элементы управления, включая перезапуск, должны оставаться доступными и не перекрывать важные части сцены.

Конкретное соотношение сторон не фиксируется. Технический механизм масштабирования и точная компоновка интерфейса пока не выбраны; они должны выполнять перечисленные требования.

## Границы реализации

Первый прототип содержит одну локацию и десять предметов, поиск нажатием, список, завершение и перезапуск. Монетизация, реклама и подсказки в MVP отсутствуют. Сюжет, персонажи, энергия, таймер, магазин, аккаунты и другие дополнительные механики не проектируются без отдельного согласования.

Не следует заранее строить инфраструктуру для будущей монетизации или сложный редактор. Детали структуры исходного кода и дополнительных зависимостей определяются только при необходимости на этапе реализации.

## Проверка будущей реализации

Проверить соответствие критериям готовности из GAME_DESIGN.md, корректность ссылок на ресурсы и уникальность идентификаторов размещений. Отдельно проверить повторные нажатия, завершение после всех находок и сброс при перезапуске. На мобильных экранах разных размеров в горизонтальной ориентации проверить сохранение пропорций сцены, совместное масштабирование фона и предметов, корректность координат и совпадение областей нажатия с видимым расположением предметов. Убедиться, что список и элементы управления доступны и не перекрывают важные части сцены.
